## (A) Must fix before execution

**A1. Any amendment could become "post hoc" because experimental fits are allowed too early (Decisions table; V1.5c; V1.5d).**
- **Issue:** V0.3 §8 says an amendment made after anyone has seen *any* V1 experimental result is post hoc (`v0.3-preregistration.md` §8, ~l.264–267).
- The plan nevertheless lets "local fits" go ahead while Decision 1 is open (plan l.14). It also allows "an internal rehearsal [that] may use the Figshare SI" (l.29), which is a benzene experimental fit.
- Decision 1's possible amendment to allow a public numerical reference, and Decision 4's possible crosswalk, would then be post hoc.
- **Fix:** in V1.5a, resolve and record Decisions 1, 3 and 4, plus the spot-check gating rule (see B3), as dated ledger entries. Make any V0.3 amendment before the first experimental fit. Until then, rehearse on synthetic D6h data only. Log the first-fit timestamp as a V1.5a gate.

**A2. The four-value verification label is required, not optional (Decision 4).**
- **Issue:** the plan treats the field as "if … mandatory". It is mandatory: the proposal requires "verification: *pending*, *synthetic-only*, *experimentally supported* or *unresolved failure*" on every page (`phase2-proposal.md:369`; `03-redesign-plan.md:503`).
- The plan's own recommendation (print the V0.3 label and counts) does not produce that field.
- **Fix:** every page carries the four-value field. Propose a crosswalk for the owner to confirm, recorded before fits:
  - `partially supported` → *pending*, with counts;
  - `explained discrepancy` → not *experimentally supported*. 03 §8 says "an explanation … does not turn a failure into experimental validation", so the closest fit is the failure class: *unresolved failure*, annotated "explained, reviewed".
  - The V0.3 label is printed beside the field.
- For 8CB, state the field explicitly (AP-DPD *pending*). The plan currently gives no label for that page.

**A3. Nobody is named to review the restricted discrepancy entries (Procedure 6; V1.5d).**
- **Issue:** the exit needs a reviewed README entry for every discrepancy (`phase2-proposal.md:375`). The plan asks for "an OWNER-authorized local reviewer who did not author the entry" but never says who writes the entries or who reviews them.
- Agents cannot see restricted values. The owner is the only person known to have local access. If the owner writes the entries, no qualifying reviewer exists, and the exit gate either cannot pass or passes on a nominal review.
- The ortho-dichlorobenzene benzene-based idealization may produce many anisotropy disagreements, so the volume could be large.
- **Fix:** add this as a fifth owner decision. Either name a second human with local access, or split each entry in two:
  - a value-free entry (estimand, geometry, vibrational corrections, solvent, likely cause) that a hosted Sol reviewer can check, if the owner decides per-cell disagreement identities may be shared, since `shareable` currently gives counts only;
  - a local numeric annex whose cell coverage a deterministic script checks and the owner attests.

**A4. The outside user may compare against a page that still says *pending* (V1.5e dependencies; guide step 4).**
- **Issue:** the participant compares their labels and counts with "our published benzene page". That page stays pending until the owner's benzene spot-check (plan l.69), yet V1.5e does not list the spot-check as a dependency. A "completed comparison" against a pending page is empty, and the exit could still pass.
- Labels also don't compare like-for-like: without a reviewed README, any participant disagreement becomes `unresolved failure` (`prereg_labels.py:98-99`).
- **Fix:** make the benzene spot-check an explicit dependency of V1.5e. Compare the cell counts (compared / agreeing / disagreeing / pending), not the dataset label.

## (B) Should fix or clarify

Add the local fit values to a local scan tier, or extend the V1.5b sentinel test to all outward files.

  - Name the full-precision output path (`run.get` or an export, not values rounded in the UI).

- **B6. Missing open questions:**

- **B7. The reproduction margin has no code.** Its rule (`max(σ, half unit)` / `2p`) is not in `prereg_labels`. Either freeze its implementation and tests in V1.5b, before any library material arrives, or say explicitly that it is deferred.
- **B8. Owner time is underestimated.** 2–4 h does not cover two spot-checks, the local runs, discrepancy entries, two full suite runs, release review and a staged-index scan for every commit. Re-estimate. Consider letting the orchestrator run the existing scan test on the laptop (it reports only `path:line`) with the owner's attestation, if the owner agrees.
- **B9. One exit criterion is missing from the audit.** 03 §8's "Every implemented model has a robot tutorial" (`03-redesign-plan.md:532`) has no explicit row. The evidence exists: `robot.py --scenario tutorial` and `fixed-tutorial`.
