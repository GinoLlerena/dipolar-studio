# V1.0 Design review: rigid molecules from XYZ

**Status: final after rounds 66–67 (2026-11-18).** D-1 (Phase 1 directories carried over by
export file) was approved by the owner on 2026-11-18.

This is the pre-implementation review that plan §8 requires. The approved proposal
(`docs/phase2-proposal.md`) makes it the gate before V1.1. It covers:

- the observable and parameter schemas;
- the inference assumptions;
- resource budgets;
- the D19 outputs;
- snapshots, hashes and journal replay;
- the contract.

It records the proposal's early decisions: how old torsion-less drafts are read, and replay
across numerical contexts. It changes no code.

**Scope, as approved:**

- fixed geometry;
- an achiral, uniaxial medium;
- the point groups C1, Cs, C2v, D2h, D3h and D6h;
- no fast internal motions;
- per-atom isotope identity;
- ¹H–¹H observations.

**History.**
- **The first draft** wrote each project at the lowest schema version that could express it.
  Round 66 showed that mixed versions break the journal's rules.
- **The second draft** migrated each directory in place. Round 67 showed that an in-place
  migration needs many new mechanisms:
  - a frozen, read-only legacy decoder;
  - a version-aware publication protocol;
  - archive replay across compactions;
  - request outcomes under changed contracts;
  - legacy result decoders.
- **This version** keeps Phase 1 directories untouched and carries projects over through their
  existing export file (D-1). That is the owner's decision.

## 1. What exists, verified in the code (rounds 66–67)

- **Project files are strict.** `Wire` models forbid extra fields. `schema_version` is
  `Literal[2]`. `migrate_project` upgrades stored payloads one version at a time, and the
  standalone `.dipolar.json` loader already reads v1 and v2 files.
- **The journal** stores a `project_schema` per record, never decreasing, with one version per
  record.
  - A compacted snapshot keeps the state, the request table (the most recent outcomes), the
    schema versions, the context and a checksum.
  - Opening a session can repair a torn tail, settle a rotation, collect blobs and compact.
    Constructing a `Journal` can create files.
- **Identity.** `science_hash` is the SHA-256 of `{numerical_context(), project}`;
  `content_hash` is the same without `next_coupling_id`. Both use the live context, as do
  `payload_hash` and `job_ops.input_hash`.
- **Replay** refuses a record, and snapshot loading refuses a snapshot, written under another
  context. Adding any context key makes every journal with records, and every snapshot,
  unreadable.
- **Staleness** compares `content_hash` when it is known, and otherwise `science_hash`.
- **Jobs.**
  - The worker receives the project JSON captured at submission. The job record stores input
    identities and options.
  - A proposal transaction can contain a project replacement alongside a job submission.
  - The worker's result file is capped at 16 MiB (`MAX_OUTCOME_BYTES`).
- **`run.get`** decodes every blob as `FitRunOut`. `project.describe.model` returns a
  unit-bearing `phi_domain`.
- **Imported geometry.**
  - An atom is `(element, x, y, z)`. XYZ elements are H, D, C, N, O, F, P, S, Cl, Br and I.
  - Only `H` atoms become ¹H spins; `D` is an atom but not a spin.
  - Atoms closer than 0.5 Å are refused (`MIN_ATOM_DISTANCE_A`).
- **`fit()` at k = 0** raises `ValueError`; the inner solve works.
- **`Problem`** accepts a full covariance (core only). It allocates a Cholesky factor, an
  identity and a dense inverse whitener.
- **The core's `order_matrix`** uses `ORDER_BASIS = (Szz, Sxx−Syy, Sxy, Sxz, Syz)`, which is not
  orthonormal. Frames are passive: x′ = Qx and S′ = Q S Qᵀ.

## 2. Decisions

### D-1 Phase 1 project directories: untouched, carried over by export (owner decision)

**Proposed (recommended).**
- **The refusal.** V1's application does **not open a directory written by an earlier
  version.** It detects one by reading the journal's first record and the snapshot header, with
  files opened read-only. It creates nothing but its instance lock, which it removes. It then
  refuses with:

  > "This project directory was written by Dipolar Studio 0.1. Open it with 0.1, export the
  > project (Data → Export, or `project.export`), and load the file into a new directory with
  > this version. The old directory is not changed."

- **Carrying the project over.** A v1 or v2 `.dipolar.json` file loads through the existing
  standalone path, migrated v2 → v3 in memory by `migrate_project`. It is the first record of the
  new directory, so its history starts there.
- **What does not carry over:** undo and redo history, runs, jobs, proposals and the request
  table. They stay in the old directory, which 0.1 still opens and verifies.
- **Why.** Nothing old is ever rewritten, so no crash, contract change or missing archive can
  damage it. The only legacy code V1 needs is `migrate_project`, which exists and is tested for
  v1 → v2.

**The alternative (not recommended now): migrate in place.** That would need, from round 67:
- a frozen, read-only legacy decoder chosen under the lock before any live `Session` or
  `Journal` exists;
- a version-aware publication protocol with one durable commit point (a generation manifest),
  covering empty tails, interrupted v2 rotations and crashes around publication;
- verified replay of archive segments across compactions, with a per-job input index (the
  `job.submitted` states);
- request outcomes kept under the legacy argument canonicalization;
- durable proposal-expiry decisions;
- legacy result-blob decoders and digest checks before publication.

That is at least one more step, and it can be added later if there are users with real
histories.

**Effect on the approved proposal.** V1.3's compatibility gate ("a migrated project and its
replayed journal converge on the same migrated identity") becomes:
- v1/v2 export files load to the same v3 identity, through the file path and through
  `project.load`;
- a Phase 1 directory is refused, unchanged byte for byte.

**The owner confirms this, or chooses the in-place migration.**

### D-2 One numerical context

- **The new global entries** (all versioned):
  - `fixed_fit` (the k = 0 path, D-8);
  - `rank_policy` (D-8);
  - `symmetry_check` (D-4);
  - `tensor_basis` (D-7);
  - `feasibility_certificate` (D-9).
- **No replay across contexts.** A V1 directory is only ever written under this context, so
  replay, snapshots, `input_hash` and staleness compare against it as today. No V1 code reads a
  record written under another context (D-1).
- **A later context change** must either keep old directories unopened, as here, or bring the
  D-1 alternative.

### D-3 Model states and transitions

A new kind, **`fixed`**, leaves the meanings of `rigid` and `jump4` unchanged. It supersedes the
proposal's wording "`rigid` without a torsion".

| State | Geometry | `kind` | `order` | `frame` | `phi_domain` | Symmetry |
|---|---|---|---|---|---|---|
| Template fit (unchanged) | biphenyl template | rigid, jump4 | as today | bisector, ring-a | required | not allowed |
| Torsion fit (unchanged) | imported, torsion set | rigid | c2z, c1 | input | required | not allowed in V1 |
| Draft (unchanged) | imported, no torsion | rigid | as stored | input | as stored | optional |
| **Fixed-geometry fit** | imported, no torsion | **fixed** | **point-group** | **symmetry** | **absent** | **required** |

**Old drafts (the early decision).** A carried-over imported draft without a torsion stays a
draft, keeping its stored domain. Readiness says:

> "declare a torsion, or declare the molecule's symmetry and choose a fixed-geometry fit"

**Entering `fixed`** (`model.set kind=fixed`) requires a declared symmetry and no torsion. It is
atomic, and the existing coupling rows are canonicalized **losslessly**:
- each row's pair is mapped to its pair orbit;
- `equivalent_pairs` and `multiplicity` are set from the orbit;
- the coupling ID, value, σ and `source_labels` / `source_equivalent_pairs` are kept;
- **the transition is refused** (`OBSERVATIONS_CONFLICT`, listing the rows) if two rows fall in
  one orbit, or if a row's stored class is not exactly its orbit (compared as sets) and is not
  a single pair of that orbit.

**Leaving `fixed`** for a draft or a torsion fit is atomic too:
- each row keeps its `equivalent_pairs` only if it is a valid class of the target model (the
  existing check in `science._validate_observation_classes`);
- otherwise the transition is refused, listing the rows.

**Resolving a conflict.** A new operation, `couplings.remove {coupling_ids, expected_science_revision}`
(additive, proposable, undoable). The user removes or re-imports rows explicitly; nothing is
dropped silently.

**Symmetry edits** use `molecule.set_symmetry {symmetry | null, expected_science_revision}`.
Clearing the symmetry (`null`) is refused while `kind = fixed`.
- **While rows exist,** a symmetry or isotope edit recomputes every observed row's **full orbit
  membership**. It is refused (`OBSERVATIONS_CONFLICT`) if any row's orbit changes: a merge, a
  split, *or* an expansion.

**The same validation** runs on load, direct edit, dry run and proposal acceptance (one
function in `science.py`).

`model.set` keeps its unit-bearing `phi_domain` argument, which must be absent for `fixed`.

### D-4 Symmetry: the declaration, validation, the averaged geometry and orbits

**The declaration**, `Molecule.symmetry`, holds:
- `point_group` ∈ {C1, Cs, C2v, D2h, D3h, D6h};
- `axes`: rows x, y, z in input coordinates. They must be orthonormal and right-handed within
  1e-9, and are re-orthonormalized (polar decomposition) for computation.
- `tolerance_a`: from 0.001 to 0.1 Å, default 0.01 Å;
- `medium`: `"achiral-uniaxial"`, the only value.

A chiral medium is refused (`MEDIUM_NOT_SUPPORTED`): it can lift enantiotopic equivalence and
the mirror reductions.

**The frame conventions** (passive: coordinates x′ = Q x, order matrix S′ = Q S Qᵀ):

| Group | Convention |
|---|---|
| Cs | z normal to the mirror plane |
| C2v | z along the C2 axis; x and y in the two mirror planes |
| D2h | x, y, z along the three C2 axes |
| D3h | z along C3; x along one C2′ |
| D6h | z along C6; x along one C2′ |
| C1 | any frame |

C2, C2h and C3v are refused for new declarations (`POINT_GROUP_NOT_SUPPORTED`); the legacy `c2z`
order stays valid on the torsion path.

**The origin** is the unweighted centroid of all atoms. An atom permutation fixes it, so a
translated XYZ file validates.

**The group action.**
- **The operations** are generated from standard generators in the symmetry frame and closed
  into the group table.
- **Matching.** Each operation g matches every centred atom x_i with the unique atom of the
  same element and mass number nearest g·x_i, within `tolerance_a`.
- **The matches must form a group action.** Every π_g must be a permutation, and π_gh =
  π_g ∘ π_h for the whole group table.
- **Guard tests only.** With `MIN_ATOM_DISTANCE_A` = 0.5 Å and `tolerance_a` ≤ 0.1 Å:
  - an ambiguous match would need two atoms within 0.4 Å;
  - an inconsistent composition would need them within 0.3 Å.

  Neither can occur in a valid project, so these checks are tested below the validation layer.

**The averaged geometry** is x*_i = |G|⁻¹ Σ_g g⁻¹ x_{π_g(i)}.
- Reindexing with k = gh gives h·x*_i = x*_{π_h(i)}, so x* is exactly symmetric.
- The fit uses x*. The stored input coordinates are unchanged; x* is derived, and the largest
  |x*_i − x_i| is reported.

**Orbits.**
- Site orbits are **symmetry-enforced chemical equivalence** under the declaration.
- An unordered pair maps to the sorted pair (π_g(a), π_g(b)), so both endpoints are permuted
  together. Pair orbits are derived **on demand for the observed pairs only** (|G| lookups per
  pair); the n² pairs are never enumerated.
- **One reduced design row per pair orbit**, from its representative (the smallest pair of spin
  IDs), so equal predictions within an orbit hold by construction.

**Equivalence.** Magnetic equivalence also needs the same resonance frequency and identical
couplings to every other spin. It is never used to merge observations.
- **The fixture is 1,4-dichlorobenzene.** H2 and H6 share a site orbit, while H2–H3 and H6–H3
  are distinct pair orbits with distinct reduced design rows.
- A specified tensor that gives them different predictions is part of the fixture. Two
  distinct rows can coincide for particular tensors.

**Conversion.** The orthonormal coordinates b (D-7) convert to the core's `ORDER_BASIS` by a
fixed linear map, tested against `order_matrix`.

### D-5 Couplings under a fixed-geometry model: one estimate per pair orbit

- **Every H atom must be a spin** in a fixed-geometry project, so orbits are complete.
- **Rows are keyed by pair orbit:** the orbit's representative pair of spin IDs, after label
  mapping.
  - Reconciliation (D5) matches existing rows by orbit key. Another member of an existing
    orbit therefore *updates that row*, keeping its coupling ID.
- **Two rows in one orbit are refused** in an import ("repeat measurements of one pair orbit are
  not accepted in this release"). Nothing is dropped.
- **The orbit fields in the CSV.**
  - An *omitted* `multiplicity` or `equivalent_pairs` is filled in from the orbit.
  - An *explicit* one must match the orbit, compared as unordered sets, or the import is refused
    with the difference.
  - The parser keeps "omitted" distinct from "1".
- **N counts rows; symmetry copies change neither N nor ν.**

### D-6 Isotopes

**One isotope table,** used on load, edit, dry run and proposal acceptance:
- **H:** the most abundant isotope; a spin.
- **D:** the element `D`, the only spelling of deuterium. `H` with mass number 2 is refused.
- **C:** 12 (default) or 13.
- **N:** 14 (default) or 15.
- **Other elements:** the most abundant isotope only.

A default mass given explicitly is normalized to absent, so each identity has one spelling.

`molecule.set_isotope {atom, mass_number | null, expected_science_revision}` applies to non-spin
atoms only (deuterating a proton removes a spin: re-import with `D`). It is revalidated
atomically against the symmetry and the orbits (D-3).

### D-7 The order parameters: basis and reductions

**The orthonormal coordinates** (Frobenius, Σ b_k² = tr S²) are

b = (√(3/2)·S_zz, (S_xx − S_yy)/√2, √2·S_xy, √2·S_xz, √2·S_yz).

Covariances, functionals and rotation tests use b. The user-facing names map to b by a fixed
linear map.

**The symmetry subspace** has dimension d, with the frames of D-4:

| Group | d | Free coordinates |
|---|---|---|
| D6h, D3h | 1 | b₁ |
| D2h, C2v | 2 | b₁, b₂ |
| Cs | 3 | b₁, b₂, b₃ |
| C1 | 5 | all |

Components that the symmetry sets to zero are reported as **fixed by symmetry**, not as
estimated by the data.

**Rotations.** A frame change acts on b by an orthogonal 5 × 5 matrix R(Q), tested against the
core's `frame_change`.

### D-8 The k = 0 fit: rank, estimands, intervals, adequacy

**The estimate.** WA_d = U Σ Vᵀ in the d reduced coordinates, with the minimum-norm solution.
- **Rank zero** (s_max = 0, or no singular value retained) is handled first: nothing is
  estimated, and no ratio is computed.
- **With N < d,** the null space is completed with the full right singular basis.

**The required rank is d. A rank is never inferred from a tolerance on the geometry.**
- **Round 67's counterexample:** C1 pair vectors (1,0,0), (0,1,0), (1,1,0) and
  (1,0,10⁻⁷) pass a 1e-6 Å coplanarity test but have rank 4. With one σ raised, the singular
  values hide the fourth direction.
- **So the only exact reductions are symmetry reductions.** A planar molecule is declared Cs,
  with its plane as the mirror. The averaged geometry then lies in the plane exactly, and
  d = 3 is the in-plane block.
- **The rank is verified** when the numerical rank r_num (singular values with
  s_i / s_max > 1e-10) equals d, with the margin s_d / s_max ≥ 1e-6.
- **Otherwise it is *rank-deficient (unverified)*,** reported with the ratios.

**Estimands.**
- **Verified rank.** Every linear functional of the d reduced coordinates is estimable. It is
  reported with its machine-readable coefficient vector in b, its estimate, its standard error,
  and exact Gaussian intervals at 68.3 % and 95 %.
- **Unverified rank.** Only the retained directions are reported, as **projected coordinates**
  (the coefficient vectors v_i). They are labelled "projection onto the retained directions",
  with `interval_support: "not supported: rank unverified"`.
- No functional is called estimable because a projection test passes.
- **Components fixed by symmetry** are reported separately, with the value 0 by declaration.
- **`fit.run(intervals=…)`** has no effect for `fixed`: exact intervals cost nothing and are
  always given when they are supported. The result's `interval_support` says which.

**Adequacy.**
- χ² = ‖W(y − A b̂)‖², with ν = N − d.
- **The p-value** is given only when the rank is verified and ν > 0. A p-value below 0.001 flags
  the fit inadequate.
- **Otherwise it is withheld,** with the code `ADEQUACY_RANK_UNVERIFIED`, or `NO_DOF` when
  ν ≤ 0.

**What these results assume.** Every statistic is conditional on the stated σ (independent
errors) and on:
- fixed geometry;
- Gaussian errors;
- an unconstrained linear estimate.

Nothing is clipped to the physical region, and principal values and axes have no intervals.

**Covariance.** A full covariance stays core-only in V1. The core refuses N > 2000 **before
allocating**: peak memory is about four N × N float64 matrices, about 128 MB at the limit.

### D-9 Admissibility, with certificates

**The question.** Does the fitted family contain a tensor with λ_min(S) ≥ −1/2? That is
equivalent to (2S + I)/3 being positive semidefinite, since tr S = 0. The family lies **inside
the symmetry subspace**.

**Nullity zero** (rank verified: r_num = d). The fitted tensor is tested directly. Within
tolerance, the result is *admissible* or *inadmissible*.

**Nullity m > 0** (rank-deficient). The family is F = {S₀ + Σ c_k N_k}, with:
- S₀ the minimum-norm tensor;
- N_k orthonormal null directions within the symmetry subspace, with m ≤ 5.

Two cases:
- **Rank zero.** F is the whole symmetry subspace, which contains S = 0. The answer is
  *feasible*, with S = 0 as the labelled representative.
- **Feasible.** A candidate in F, verified by an eigenvalue computation:
  - λ_min ≥ −1/2 gives *feasible*;
  - −1/2 − ε ≤ λ_min < −1/2 gives *feasible within tolerance* (ε = 1e-9).
- **Infeasible.** A dual matrix Z, verified in floating point, such that:
  - Z ⪰ −ε·I;
  - |tr Z − 1| ≤ ε;
  - |⟨Z, N_k⟩| ≤ ε for every k;
  - ⟨Z, S₀⟩ < −1/2 − (2 + √(3m/2))·ε − δ, with δ = 1e-12 for arithmetic.

  **Why this is sound in finite precision (round 67).** S₀ is the minimum-norm point and the N_k
  are orthonormal, so any physical completion has ‖c‖₂ ≤ √(3/2): a physical S has
  ‖S‖_F ≤ √(3/2). This bounds the error that the tolerances on Z can introduce. So the inequality
  above proves max_F λ_min < −1/2.
- **Otherwise *undetermined*.** A solver's termination never decides on its own.

**Tests:** boundary cases, repeated eigenvalues, two frames, rank zero, and the round 65 rank-1
example.

### D-10 The result and its contract

**The fixed result.** `fit.run` still returns a job submission. A fixed run's result is a new
typed model, `FixedRunOut`, with these fields:
- `rank {required: d, numerical, verified, ratios}`;
- `components [{name, status: estimated | fixed-by-symmetry | projected, coefficients_b,
  estimate, se, intervals {68.3, 95} | null, interval_support}]`;
- `covariance_b`: d × d, or the retained block, with the coordinate list;
- `null_directions_b`;
- `adequacy {chi2, nu, p_value | null, status: given | inadequate | withheld | no-dof, code?}`;
- `admissibility {status, representative?, certificate_summary}`;
- `rows [{coupling_id, pair, orbit, observed, sigma, predicted, residual}]`, which the
  `run.report` CSV needs;
- `symmetry {group, axes, tolerance_a, medium, max_displacement_a}`;
- `assumptions`, `warnings` (coded), `provenance` (input identities, context, versions) and
  `estimand`.

Search-era fields are absent.

**Decoding.** The decoder is chosen from the **run record's model kind**, which is trusted
metadata, not from the blob. The report renders a fixed run without φ.

**Contract classification (D20).** This is a **breaking** change, declared as such:
- `run.get` can return `FixedRunOut`;
- `project.describe.model` has no `phi_domain` for a fixed project.

Old clients that assume the search-era result, or a `phi_domain` on every model, fail on a
fixed project. The contract version moves from 0.10.0 to 0.11.0 (SemVer 0.x). The registry
snapshot and the changelog list it as breaking.
- **Within that version:** the web client and the Python API ship in the same wheels.
- **Gates:** for projects without a fixed model, the responses are unchanged, so old clients
  keep working on them (a test with the 0.10.0 TypeScript types).

**New operations** (additive):
- `molecule.set_symmetry`;
- `molecule.set_isotope`;
- `couplings.remove`.

All take `expected_science_revision`, are proposable, have dry runs and are undoable. Each gets
registry examples, the snapshot and Python/HTTP parity. `fit.preview` and `fit.landscape` refuse
a fixed model (`NO_TORSION`).

### D-11 Budgets

Every limit is checked before allocation, and on the direct call, the dry run, proposal
acceptance and the worker. The times are confirmed on named hardware in V1.1 and V1.2, and
recorded under `docs/validation/data/`.

| Work | Limit | Budget to confirm |
|---|---|---|
| Symmetry validation | ≤ 1000 atoms, ≤ 24 operations | ≤ 1 s CPU, ≤ 200 MB |
| Orbits | observed pairs only, ≤ the coupling limit | O(\|G\|) per pair |
| Fixed fit: admission | N ≤ 20 000 rows, so the serialized result (about 300 bytes per row) stays well under the worker's 16 MiB cap; `FIT_TOO_LARGE` beyond | ≤ 2 s, ≤ 100 MB |
| Core covariance | N ≤ 2000 | ≤ 128 MB peak |
| Certificates | m ≤ 5 null directions; rank zero is special-cased | ≤ 0.1 s |
| Migration | none (D-1) | none |

The admission limit and the 16 MiB cap are tested together **through the process worker**, at
the limit.

## 3. Gates carried into the steps

**V1.1, the core fit:**
- **Frozen first:** the noiseless fixtures, the fixed-seed noisy regression and the coverage
  protocol (1000 seeds, band 64.5–72.1 %), with their expected values and tolerances, before
  evaluation.
- **Recovery:**
  - a nonplanar C1 rank-5 fixture;
  - a planar molecule declared Cs (d = 3);
  - a rank-deficient C1 fixture, which must report *unverified*;
  - round 67's near-planar counterexample, which must report *unverified*, with adequacy
    withheld.
- **The rank cases:** verified; unverified; N < d; rank zero.
- **R(Q)** orthogonal and equal to `frame_change`. Rotated predictions and functionals are equal,
  with repeated singular values compared as subspaces.
- **The certificate cases of D-9.** The covariance cap is refused before allocation.
- **The φ path unchanged:** the biphenyl gates and 8CB.

**V1.2, symmetry:**
- recovery and predictions for every supported group, including ideal benzene's single S_zz;
- a translated XYZ validates;
- refusals: a group the geometry lacks, a chiral medium, an unsupported group; the guard tests
  for ambiguity and a non-action;
- relabelling and joint endpoint permutation leave the fit unchanged;
- isotopes: benzene-d₁ refused as D6h and accepted as C2v; ¹³C splits an orbit;
- the 1,4-dichlorobenzene equivalence fixture;
- symmetry copies leave N and ν unchanged;
- benzene's scale degeneracy;
- the budgets.
- **Checkpoint:** if V1.2 proves bigger than a Phase 1 step, it splits into order reductions,
  then orbits and isotopes. This is re-baselined before V1.2 starts.

**V1.3, the application:**
- **D-1:**
  - a Phase 1 directory is refused and left unchanged byte for byte, journal-only and
    snapshot-plus-journal fixtures included;
  - v1 and v2 export files load to the same v3 identity through both paths.
- **D-3 transitions:** entering and leaving `fixed` with populated rows; every refusal; on load,
  edit, dry run and proposal acceptance.
- **D-5:** another orbit member updates the same row; repeats are refused; omitted and explicit
  classes are handled.
- **D-6:** the isotope table on every path.
- **D-10:** φ-free reports; the contract's breaking-change classification; old-client behaviour
  on non-fixed projects; registry, Python and HTTP parity.

**V1.4:** the Fit workspace without φ, and the Structure view for one-ring molecules.

**From the approved proposal:**
- the experimental criteria are preregistered (V0.3) before any experimental fit;
- when V1 code starts is still the owner's decision, before V1.1.

## 4. Risks

- **D-1 is a narrowing.** Old histories stay in 0.1 directories. In-place migration remains
  available as a later step if it is needed.
- **The dual certificate** needs a small dedicated solver. Without a verified certificate the
  answer is "undetermined".
- **Symmetrization** moves atoms by up to `tolerance_a`, and the result states it.
- **Declaring planar molecules Cs** is a modelling requirement users must learn. A planar
  molecule fitted as C1 reports *unverified* and withholds adequacy. The Data workspace suggests
  Cs when every spin lies within `tolerance_a` of a plane. That is only a suggestion: it is
  never certified.
