# V1.0 Design review: rigid molecules from XYZ

**Status: draft for review (2026-11-18).** This is the pre-implementation review that plan §8
requires and that the approved proposal (`docs/phase2-proposal.md`) makes the gate before V1.1.
It covers:

- the schemas;
- the inference assumptions;
- resource budgets;
- the D19 outputs;
- hashes, snapshots and journal replay;
- the contract.

It also records the two early decisions the proposal asks for: how old torsion-less drafts are
read, and replay across numerical contexts. It changes no code.

**Scope, as approved:**
- fixed geometry;
- an achiral, uniaxial medium;
- the point groups C1, Cs, C2v, D2h, D3h and D6h;
- no fast internal motions;
- per-atom isotope identity;
- ¹H–¹H observations.

## 1. What exists, verified in the code

- **Projects** (`dipolar_app.project`) are strict and immutable: `Wire` forbids extra fields.
  The `schema_version` is `Literal[2]`, and migrations run in `migrate_project`.
- **Imported geometry** is `ImportedGeometry(source_format, atoms, torsion | None)`. An atom is
  `(element, x, y, z)`.
  - XYZ elements are H, D, C, N, O, F, P, S, Cl, Br and I. Only `H` atoms become spins, which
    are ¹H only.
  - So **a deuterium is already expressible**, as element `D`. Other isotopes (¹³C, ¹⁵N) are not.
- **The model** is `ModelSpec(kind ∈ {rigid, jump4}, order ∈ {bisector-diagonal, c2z, c1},
  frame, phi_domain_deg)`. `phi_domain_deg` is required.
- **Fitting** imported geometry requires a torsion (`science._problem_for`). `fit()` fails at
  k = 0 (round 63).
- **Identity.**
  - `science_hash(project)` is the SHA-256 of `{numerical_context(), project}`.
  - `content_hash` is the same without `next_coupling_id`; staleness uses it (M3 step 2).
  - `payload_hash` uses the **current** `numerical_context()`.
- **Replay** (`session._replay_records`):
  - it refuses any record whose stored `numerical_context` differs from the current one ("a
    migration is required");
  - it checks each record's `science_hash` with `_recorded_hash`, which uses the current
    context.
  - So **adding any key to `numerical_context()` today breaks the replay of every existing
    journal.**
- **Numerical context** today: `nuclide_table`, `forward_model`, `biphenyl_template`,
  `inner_solver`, `rank_rtol` (1e-10) and `admissibility_atol` (1e-12).
- **Jobs** snapshot their input project. A run is stale when the current `content_hash` differs
  from its input's.

## 2. Decisions

### D-1 Schema: version 3 only for projects that use it

The proposal said "schema v3 with a migration". **This review narrows it:** a project is
written as **version 2 whenever it can be**, and as version 3 only when it uses a version-3
feature.

- **Why.** Rewriting every project as v3 changes every project's hash (the payload includes the
  schema version) and makes every existing run stale. Phase 1 has not had a migration with
  stored runs before. Keeping v2 projects byte-identical keeps their identity, replay and
  staleness exactly as they are: the safest compatibility gate there is.
- **The rule.**
  - `schema_version: Literal[2, 3]`.
  - The writer emits the lowest version that expresses the project.
  - A v3 field present in a v2 payload is refused, and a v3 payload with no v3 field is
    normalized to v2. So one project has exactly one canonical payload.
  - An older application reading a v3 file refuses it with "unsupported project schema_version
    3" (`migrate_project` already says this).
- **The new fields**, all v3-only and omitted when absent:
  - `Atom.mass_number: int | None`. Absent means the most abundant isotope. `D` stays an
    element, as today, for compatibility; `H` with `mass_number = 2` is refused in favour of
    `D`, so a deuterium has one spelling.
  - `Molecule.symmetry: Symmetry | None`, holding:
    - `point_group` ∈ {C1, Cs, C2v, D2h, D3h, D6h};
    - `axes`: a 3 × 3 matrix, its rows the symmetry frame's x, y, z in input coordinates,
      orthonormal and right-handed within 1e-9;
    - `tolerance_a`: the largest atom displacement allowed by the symmetry check, from 0.001 to
      0.1 Å, default 0.01 Å.
  - `medium: Literal["achiral-uniaxial"]`, the only value accepted in this release. It is
    stored with the symmetry, so the assumption is explicit in every v3 project. A chiral
    medium has no value to choose: it is refused at the API with a coded error,
    `MEDIUM_NOT_SUPPORTED`.
  - In `ModelSpec`:
    - `order` gains `"point-group"`: the reduction comes from the declared symmetry;
    - `frame` gains `"symmetry"`;
    - `phi_domain_deg` becomes `None` exactly when the model has no torsion.
- **Couplings** keep their shape. For a v3 rigid model the server **derives**
  `equivalent_pairs` and `multiplicity` from the pair orbit (D-4). A user-supplied class must
  equal the derived one, or the import is refused with the difference.

### D-2 Old imported drafts without a torsion keep their meaning

A v2 imported project without a torsion is a draft: "declare a torsion to fit". **Migration
does not change that.** It becomes fittable as a rigid molecule only when the user declares a
symmetry (C1 is allowed, meaning "no symmetry"). Readiness then says:

> "declare a torsion, or declare the molecule's symmetry to fit it as a rigid molecule"

Nothing becomes fittable silently, and a v2 draft's file and hash do not change until the user
acts.

### D-3 The numerical context is scoped to the features a project uses

- **The rule.** `numerical_context(project)` = the Phase 1 base entries, **plus** the entries
  for any feature the project uses. A v2 project uses none, so its context, hashes, replay and
  staleness are byte-for-byte as today.
- **New entries, for v3 rigid projects only:**
  - `rigid_linear_fit` (the k = 0 path's version);
  - `structural_rtol`, `weak_rtol` (D-6);
  - `symmetry_check` (the validation algorithm's version);
  - `tensor_basis` (the orthonormal basis, D-5);
  - `feasibility_solver` (D-7).
- **Replay.** A record is checked against the context of the project *at that record*. Its
  `science_hash` is checked under the context **stored in the record** (`_recorded_hash` takes
  the record's context, not the current one).
  - A record whose context is neither the current base nor a known, declared-compatible older
    context is still refused, as today.
  - The table of known contexts starts with one entry, the Phase 1 base.
- **Why.** No change to a number on the φ path is planned, so a φ-path project must keep its
  identity. A rigid project gets an identity that changes whenever one of its own numerical
  choices changes (D11).

### D-4 Symmetry validation and orbits

- **Validation.** For each operation g of the declared group (its matrices in the symmetry
  frame), the transformed atom set must match the original by a **bijection that preserves
  element and mass number**, every atom moving at most `tolerance_a`. The match is the unique
  nearest same-kind atom; ambiguity within the tolerance is refused. If validation fails, the
  declaration is refused, naming the operation and the worst atom.
- **Symmetrization.**
  - The fit uses the **group-averaged geometry**: each atom becomes the mean of its images
    under the group, mapped back. Symmetry-equivalent pairs then have exactly equal predicted
    couplings.
  - The largest displacement is reported. The input coordinates stay stored unchanged; the
    averaged ones are derived, never journaled.
- **Orbits.** Site orbits and unordered-pair orbits come from the same validated permutations.
  - **Both endpoints** of a pair are permuted together, and an unordered pair is its sorted
    tuple.
  - Pairs between different isotopes or elements are never merged.
- **Observations: one estimate per pair orbit.**
  - Two coupling rows in the same orbit are refused ("repeat measurements of one class are not
    accepted in this release").
  - The row's pair is the orbit's representative; `equivalent_pairs` lists the orbit, and
    `multiplicity` is its size.
  - **N counts rows**, never multiplicity.
- **Chemical versus magnetic equivalence.**
  - Orbits are *chemical* equivalence under the declared symmetry.
  - Magnetic equivalence (equal couplings to every other spin) is a property of the spin system
    and is not used to merge observations. The dataset README states which couplings the
    spectral analysis reported.
  - A test molecule (1,4-dichlorobenzene: H2 and H6 are chemically equivalent, but couple
    differently to H3) checks that chemically equivalent sites with different couplings are not
    merged.

### D-5 The order parameters: reductions and an orthonormal basis

- **The basis.** Internally, S has the orthonormal coordinates
  `b = (√(3/2)·S_zz, (S_xx − S_yy)/√2, √2·S_xy, √2·S_xz, √2·S_yz)` (Frobenius, Σ b_k² = tr S²).
  Every covariance, estimable functional and rotation test uses b. The user-facing names
  (`Szz`, `Sxx-Syy`, …) stay as they are, through a fixed linear map.
- **Reductions,** in the symmetry frame, as linear constraints on b:

  | Point group | Free | Constraint |
  |---|---|---|
  | D6h, D3h (z the n-fold axis) | 1 | only b₁ |
  | D2h, C2v (axes on the C2 axes) | 2 | b₁, b₂ |
  | Cs (z normal to the plane) | 3 | b₁, b₂, b₃ |
  | C1 | 5 | none |

  C2, C2h and C3v (in the proposal's table) are outside the first supported set. They are
  refused with `POINT_GROUP_NOT_SUPPORTED`.
- **Rotation equivariance.** The frame change acts on b by an orthogonal 5 × 5 matrix R(Q). A
  test checks R(Q) against `frame_change` for random rotations, and that R(Q) is orthogonal.

### D-6 The k = 0 fit: rank classes, intervals, adequacy

- **The estimate.** b̂ = argmin ‖W(y − A b)‖², the minimum-norm solution, from the SVD of the
  whitened design WA = U Σ Vᵀ.
- **Rank classes**, by s_i / s_max:
  - **structural zero:** ≤ `structural_rtol` = 1e-13. This is at rounding level (about 500 ε),
    where a planar or collinear geometry or a symmetry reduction puts it.
  - **numerically dropped:** `structural_rtol` < s_i / s_max ≤ `rank_rtol` (1e-10, unchanged).
    The direction is set to zero by the cutoff although the data carry it.
  - **weak:** `rank_rtol` < s_i / s_max < `weak_rtol` = 1e-6. The direction is kept, with its
    large variance, and flagged.
  - **resolved:** everything else.
- **Estimable functionals.** cᵀb is estimable when c is in the row space of WA (the retained
  right-singular vectors). Its variance is Σ_i (cᵀv_i)² / s_i². The result reports:
  - the retained directions v_i, in b coordinates, with their estimates (u_iᵀWy)/s_i and
    standard errors 1/s_i;
  - the named components that are estimable on their own (their c lies in the row space within
    1e-9), with their standard errors.
- **Adequacy.**
  - χ² = ‖W(y − A b̂)‖², with ν = N − r.
  - The p-value is given when **every dropped direction is a structural zero** and ν > 0.
  - With a numerically dropped direction, the adequacy is **withheld**, with the code
    `ADEQUACY_RANK_NUMERICAL`. With ν = 0, there is no p-value and no adequacy claim.
  - A weak direction does not withhold the p-value (it is retained), but it is flagged.
- **Intervals.**
  - The interval of an estimable functional is estimate ± z·se. This is exact under:
    - fixed geometry;
    - Gaussian errors with known covariance (independent when σ is diagonal);
    - an unconstrained linear estimate.
  - Nothing is clipped to the physical region. Principal values and axes are reported without
    intervals ("interval not supported: nonlinear").
  - A full covariance Σ, when supplied, replaces W with the whitener the core already has
    (`Problem.covariance`).
- **Coverage.** The M1 protocol (1000 seeds, 68.3 %, band 64.5–72.1 %) on the estimable
  components of three fixtures: rank 5, rank 3 and the D2h case. The coverage is exact in
  theory, so this is a check on the implementation.

### D-7 Admissibility of a partly determined tensor

- **The question.** If r = 5, admissibility is checked on b̂ as today: (2S + I)/3 positive
  semidefinite, which is equivalent to λ_min(S) ≥ −1/2.
- **If r < 5,** the data fix only the estimable part. The question becomes: is there **any** S
  in the affine family b̂ + span(null directions) with λ_min(S) ≥ −1/2?
  - λ_min is concave, so maximizing it over at most four null coordinates is a convex problem.
  - It is solved with bounded iterations by a subgradient-free method (SLSQP on the epigraph
    form t ≤ λ_min, with a fixed iteration cap), from the minimum-norm point.
- **The result** is one of:
  - **feasible**, with the maximizing S as a *labelled representative*;
  - **infeasible**, with the best λ_min;
  - **undetermined**, if the solver does not certify either within its cap.
- **Not changed:** the φ path keeps today's flag.
- **The test.** The rank-1 example of round 65 gives the same answer in two frames.

### D-8 D19 outputs, the self-describing result

A k = 0 result adds:
- `geometry_parameters: []`;
- `rank`: the four classes, with counts and directions;
- `estimable`: the directions, estimates and standard errors in b, and the named components
  that are estimable alone;
- `unidentified`: null directions with no error bars, as today;
- `adequacy`: `{chi2, nu, p_value | null, status: given | withheld | no-dof, reason}`;
- `admissibility`: `{status: admissible | inadmissible | feasible | infeasible | undetermined,
  representative?}`;
- `assumptions`: the interval assumptions in words;
- `symmetry`: the declared group, axes, tolerance, largest displacement and medium;
- `orbits`: each coupling's orbit;
- `estimand`: "order parameters of the rigid fixed geometry, in the declared symmetry frame".

The report (`run.report`) and the Fit workspace render these, and the report says so whenever
adequacy is withheld.

### D-9 Resource budgets

| Work | Bound | Cost at the bound |
|---|---|---|
| Symmetry check | ≤ 1000 atoms (`MAX_ATOMS`), ≤ 24 operations (D6h) | 24 nearest-neighbour matchings of 1000 points, vectorized: well under 1 s |
| Orbits of observed pairs | ≤ 100 000 couplings (`MAX_COUPLINGS`) | 24 lookups per pair |
| k = 0 fit | N × 5 SVD | N = 100 000: tens of ms |
| Feasibility | ≤ 4 variables, ≤ 200 iterations | ms |
| Coverage gate | 1000 seeds × 3 fixtures of a linear fit | seconds (`-m slow` not needed) |

Each bound is enforced at the API with a coded error. None reaches the job timeout.

### D-10 Contract

Additive operations and fields, a **minor** version bump (D20):

- `molecule.set_symmetry {point_group, axes, tolerance_a, medium}` (proposable, dry-run). A
  failed check returns the operation and the worst atom.
- `molecule.set_isotope {atom, mass_number}`.
- `model.set` accepts `order: "point-group"`, `frame: "symmetry"` and `phi_domain_deg: null`
  for a torsion-free imported molecule.
- `fit.run`, `run.get` and `run.report` carry the D-8 fields.
- `fit.preview` and `fit.landscape` refuse a k = 0 project with `NO_TORSION`. There is nothing
  to scan.

Every new operation gets registry examples, Python/HTTP parity tests and the snapshot.

## 3. Gates carried into V1.1–V1.3

From this review:

- v2 projects, journals, snapshots and runs are unchanged byte-for-byte. The whole Phase 1
  suite and the 8CB gates pass untouched.
- A v3 payload with no v3 field normalizes to v2. A v3 field in a v2 payload is refused.
- Replay checks each record under its own stored context. An unknown context is refused.
- A v2 imported draft without a torsion is still "not ready" after loading.
- R(Q) is orthogonal and equals `frame_change` for random Q.
- The rank classes, with an exactly planar fixture (structural) and a 1e-12 out-of-plane
  perturbation (numerically dropped: adequacy withheld).
- Feasibility: the same answer in two frames; feasible and infeasible constructed cases.
- Symmetry:
  - refused when the geometry lacks it;
  - refused when two atoms are ambiguous within the tolerance;
  - benzene-d₁ (one `D`) refused as D6h and accepted as C2v.
- One estimate per orbit: repeats are refused, and N counts rows.

## 4. Risks

- **The SLSQP feasibility** may need care near λ_min = −1/2. The fallback is "undetermined",
  never a guess.
- **Two schema versions in the writer** add a normalization step. It is covered by the
  round-trip tests above.
- **Symmetrization** can move atoms by up to `tolerance_a`. The fit then describes the averaged
  geometry, which the result states (D-8).
